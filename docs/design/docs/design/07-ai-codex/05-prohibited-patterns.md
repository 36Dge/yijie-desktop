# 禁止模式


## 文档状态

- 状态：Accepted
- 版本：2.0.0
- 最后更新：2026-09-05
- 适用仓库：`yijie-desktop`
- 适用技术栈：Tauri v2、Vue 3、Vite、TypeScript、Pinia、Vue Router、Naive UI、ECharts、Lucide
- 默认语言：中文

## 目标

列出 AI/Codex 在前端开发中禁止出现的模式。

## 适用范围

适用于 Codex/AI 生成或修改 `yijie-desktop` 前端代码的所有任务。

## 规范正文

## 禁止视觉模式

- 页面内硬编码颜色、字号、圆角、阴影。
- 每个页面自定义一套卡片和按钮样式。
- 直接使用随机 SVG 或未知来源图片。
- 不同图标库混用。
- 亮色页面、导航或业务分组恢复旧灰绿铺底；用品牌软底替代结构白底。
- 青柠实色按钮配白字，或用浅青柠作为白底正文、细线链接和唯一焦点环。
- 暗色沿用绿色偏色背景，或直接反转亮色 Logo。
- 使用旧手提袋 Logo、PNG 截图 Logo，或把 PNG 嵌进 SVG 冒充矢量。
- 为本次换色重新设计字号、间距、圆角尺度、布局或交互。

## 禁止架构模式

- 页面承载复杂业务逻辑。
- API 类型手写而不从 contracts 或统一类型来源派生。
- 状态散落在多个组件。
- 页面直接处理平台 token 或敏感数据。

## 禁止 UX 模式

- 长任务只有 spinner。
- 错误没有下一步。
- 高影响操作无确认入口。
- 风险结论绝对化。
- 数据图表无单位、无时间范围。

## AI / Codex 必须遵守

- 必须先读取本设计系统相关文档。
- 必须优先复用已有组件和 token。
- 必须输出可运行、可测试、可审查的代码。
- 不允许引入未经批准的新库、新风格、新视觉资产。

## 实现要求

所有 Codex 任务应在 prompt 或 `AGENTS.md` 中引用本规范。复杂页面生成前应先输出页面结构计划，再写代码。

## 验收清单

- [ ] 符合 design token。
- [ ] 使用 `Yj*` 组件。
- [ ] 图标走 registry。
- [ ] 状态完整。
- [ ] 无硬编码视觉值。
