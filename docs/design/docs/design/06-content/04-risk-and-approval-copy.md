# 风险与审批文案规范


## 文档状态

- 状态：Accepted
- 版本：1.0.0-final
- 适用仓库：`yijie-desktop`
- 适用技术栈：Tauri v2、Vue 3、Vite、TypeScript、Pinia、Vue Router、Naive UI、ECharts、Lucide
- 默认语言：中文

## 目标

定义当前阶段对高影响操作和未来审批策略的文案承接方式。

## 适用范围

适用于界面文案、状态文案、错误文案、按钮、提示、审批、Agent 消息和数据说明。

## 规范正文

操作审批策略后期由业务定义，本规范不擅自定义哪些操作必须审批，也不定义风险等级枚举。

但 UI 必须具备承接能力：

- 能展示“需要确认”的操作。
- 能展示操作影响范围。
- 能展示工具调用摘要。
- 能展示后端返回的风险字段。
- 能展示确认、取消、查看详情。

## 当前通用文案结构

```text
请确认是否执行此操作
该操作可能影响店铺数据。请确认操作内容、影响范围和执行对象。
```

## 高影响操作文案原则

不使用“立即自动执行”作为默认文案，应使用“确认执行”“提交审批”“查看影响范围”等可控表达。

## AI / Codex 必须遵守

- 界面文案默认中文。
- 文案必须专业、直接、可执行。
- 不允许夸大 AI 能力或给出不可验证承诺。
- 不允许使用模糊、娱乐化或过度口语表达。

## 实现要求

文案常量可以进入 `src/i18n/zh-CN.ts` 或页面局部常量，但必须遵守统一语气。错误码到文案的映射应集中管理。

## 验收清单

- [ ] 文案为中文。
- [ ] 主操作动词清晰。
- [ ] 错误说明包含解决方式。
- [ ] 风险文案不绝对化。
- [ ] AI 结果没有过度承诺。
