# 可访问性基线


## 文档状态

- 状态：Accepted
- 版本：1.0.0-final
- 适用仓库：`yijie-desktop`
- 适用技术栈：Tauri v2、Vue 3、Vite、TypeScript、Pinia、Vue Router、Naive UI、ECharts、Lucide
- 默认语言：中文

## 目标

定义易界桌面端 UI 的最低可访问性要求。

## 适用范围

适用于所有颜色、文本、按钮、表单、图表、图标、弹窗、任务状态和键盘交互。

## 规范正文

可访问性是易界 UI 的基础质量门禁，不是后期优化项。

## 颜色与对比

- 正文、标题、按钮、表格内容必须满足基本对比要求。
- 不允许只靠颜色表达成功、失败、风险、等待审批等状态。
- 图表必须提供图例、标签或 tooltip，不只依赖色彩区分。

## 键盘与焦点

- 可交互元素必须可键盘访问。
- 弹窗打开后焦点必须进入弹窗，关闭后回到触发元素。
- 焦点样式必须清晰，不允许去掉 outline 后没有替代样式。

## 语义与辅助信息

- 图标按钮必须有 aria-label 或文字提示。
- Loading、Error、Empty 状态必须有文字说明。
- 表单错误必须关联具体字段。

## 动效

动效不能影响任务理解。对进度、状态变化使用轻量动效，不使用大幅位移和长时间循环动画。

## AI / Codex 必须遵守

- 不允许只使用图标按钮且没有标签。
- 不允许删除 focus 样式。
- 不允许用红/绿作为唯一状态区分。
- 不允许让加载态没有可读文案。
- 不允许图表没有 tooltip 或数据说明。

## 实现要求

组件封装时必须提供 `aria-label`、`role`、键盘行为、focus 样式和禁用状态。ECharts 图表必须提供文本摘要区域或关键指标卡作为补充。

## 验收清单

- [ ] 键盘可操作核心流程。
- [ ] 状态表达不只依赖颜色。
- [ ] 图标按钮有可访问名称。
- [ ] 表单错误明确可定位。
- [ ] 图表有文本化结论或摘要。
