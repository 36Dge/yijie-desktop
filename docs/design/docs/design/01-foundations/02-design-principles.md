# 设计原则


## 文档状态

- 状态：Accepted
- 版本：1.0.0-final
- 适用仓库：`yijie-desktop`
- 适用技术栈：Tauri v2、Vue 3、Vite、TypeScript、Pinia、Vue Router、Naive UI、ECharts、Lucide
- 默认语言：中文

## 目标

定义所有易界 UI 的最高级设计判断标准。

## 适用范围

适用于界面布局、组件选择、文案表达、动效、图表、Agent 状态和审批体验。

## 规范正文

## 原则一：专业可信

易界面向真实店铺经营，界面必须稳定、克制、清晰。不要使用娱乐化、游戏化或过度拟物风格。

## 原则二：AI 可控

Agent 执行过程必须可见。用户应看到任务阶段、工具调用、等待审批、完成状态、失败原因和下一步建议。

## 原则三：数据优先

经营分析页面必须先展示结论、关键指标和风险，再展示明细。图表服务于判断，不用于装饰。

## 原则四：风险前置

任何可能影响店铺经营结果的操作，都必须在 UI 中预留确认、审批、撤销或审计入口。

## 原则五：一致胜过炫技

不同页面的布局、间距、图标、按钮、表格、卡片、状态色必须一致。AI 不允许为单个页面创造新的视觉语言。

## AI / Codex 必须遵守

- 生成页面前先选择适用 pattern。
- 不允许为了“好看”破坏信息层级。
- 不允许隐藏 Agent 执行过程。
- 不允许把风险提示做成弱提示。
- 不允许引入一次性样式。

## 实现要求

组件必须通过 design token 控制视觉；页面必须复用统一布局组件；Agent 状态必须使用统一状态组件；数据展示必须使用统一数据组件和 ECharts 主题。

## 验收清单

- [ ] 页面能在 5 秒内说明核心任务。
- [ ] 首屏有明确主操作或主要结论。
- [ ] Agent 任务有过程可见性。
- [ ] 风险、错误、空态、加载态完整。
- [ ] 没有孤立的视觉样式。
