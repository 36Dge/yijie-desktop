# 插件市场 Pattern


## 文档状态

- 状态：Accepted
- 版本：1.0.0-final
- 适用仓库：`yijie-desktop`
- 适用技术栈：Tauri v2、Vue 3、Vite、TypeScript、Pinia、Vue Router、Naive UI、ECharts、Lucide
- 默认语言：中文

## 目标

定义易界 Skill/Plugin 展示、安装、配置和权限说明页面。

## 适用范围

适用于对应页面 pattern 的路由页面、业务组件、状态管理、接口接入和文案。

## 规范正文

插件市场必须展示插件名称、能力范围、适用平台、需要权限、数据访问范围、版本、发布者和安装状态。插件安装前必须说明权限和影响范围。

插件详情页要区分“能力说明”“所需权限”“使用示例”“版本记录”。

### Skill 广场卡片与交互（2026-09-07 用户确认）

广场卡片遵循用户已确认的精简展示：保留名称、能力描述、独立功能图标及真实操作/异常状态；不恢复版本、来源、风险、适用、工具数量、许可等底部元信息，不显示“可安装 · 需工具”提示。底层目录数据、权限校验、安装和启停行为保持原样。

2026-10-18 用户更新：38 个 Skill 卡片与 5 个分类标题统一使用 Codex 内置生图工具生成的本地彩色图标，取代原有线性图标。采用浅彩色底与饱和色实心主体，每个技能依据能力描述设计独立意象；不复制平台官方标志。卡片图标保持 48px，分类图标为 24px，分别使用既有 lg/sm 圆角 token；移除卡片图标原有的线性边框与白色底板。亮暗主题共用图像，页面与卡片仍采用各自主题表面。

素材由 `src/icons/skill-artwork.ts` 按稳定技能 ID 映射，分类由 category 映射；未来未映射技能回退至本分类彩色图标。图片作为装饰使用空 alt 和 `aria-hidden`，文字名称提供语义。资产与逐项生图提示词位于 `src/assets/skills/`，不把图片路径写入目录协议、安装包或持久状态。普通操作按钮继续使用现有 `YjIcon`。

可操作卡片在 hover 或内部 focus 时显示 1px 品牌青柠边框，安装按钮同时变为青柠圆底与石墨加号。只有按钮触发操作、显示手形指针，卡片本体保持普通内容容器语义。默认、只读、不可安装及忙碌卡片保持中性；卸载、错误和权限语义不改。键盘实际焦点仍显示 2px 中性轮廓，青柠边框不替代焦点指示。

保持现有三列布局、尺寸、字重、行高、圆角和间距。卡片底色不随 hover 改变，无位移、投影或发光；颜色过渡使用 `--yj-motion-fast`（120ms），减少动态效果时关闭。安装按钮主题覆盖限定于 `skill-card-theme.ts`，局部 hover 变量只引用现有 token，不修改全局按钮主题。

2026-10-19 技能状态与布局修正：聊天的新任务和回复输入框内，「管理技能」均显式进入
`/plugins?tab=skills`；侧栏扩展入口仍默认专家。弹窗仅列出已安装技能，保留停用项，
便于用户再次启用；是否启用由真实开关状态表达。

正常技能卡片不显示「未安装」「已停用」「模型可用」标签；加号表示安装入口，
开关表示已安装技能的启停状态，ready/degraded 使用同一规则。正在安装/卸载/同步、
失败、受阻和不兼容状态继续明确反馈，不把 enabled 直接当作 runtimeVisible。
异常提示独立于标题行，名称固定单行省略并保留完整 title，描述预留两行高度。
操作区固定 40px 宽，已安装卡片的卸载入口放在开关下方，hover/focus 时显示且不挤压正文。
普通卡片等高、同排拉伸；真实异常说明可扩展高度并完整换行，避免为了尺寸裁掉恢复信息。

`contract-impact = none`：仅修正 Desktop 进程内导航、状态展示和卡片几何；
Desktop/API/Agent Host 跨进程交互、Native IPC、安装/启停权限及本地持久化/重放边界均无可观察变化。

## AI / Codex 必须遵守

- 新页面必须先匹配既有 pattern；没有匹配项时先补 pattern 文档。
- 不允许在页面中重新创造布局、状态和交互流程。
- 必须包含 loading、empty、error、permission denied 状态。
- 涉及 Agent 的页面必须展示过程和结果。

## 实现要求

页面文件放在 `src/pages/` 对应业务目录，复杂逻辑进入 `src/domain/` 或 composables。页面只负责组合组件和绑定状态，不承载复杂业务规则。

## 验收清单

- [ ] 页面结构符合 pattern。
- [ ] 主操作明确。
- [ ] 数据和状态完整。
- [ ] 风险/权限/错误已覆盖。
- [ ] 组件复用而非页面堆叠。

### 连接器卡片与状态对齐（2026-10-08）

连接器市场卡片的悬停、键盘聚焦描边采用与 Skill 广场相同的品牌青柠；未安装且非忙碌项的加号保持常态透明，悬停/聚焦显示 36px 青柠圆底和石墨加号，按下采用品牌 active 色。卡片仍沿用点击打开详情的现有交互，不新增直接安装操作；忙碌和已安装状态仍由真实图标表达，保留键盘可见焦点。

「已安装」页签采用与市场相同的三列网格、12px 间距和 720px / 480px 容器断点，每个连接器为独立卡片，即使只有一个也不横贯整行。保留名称、两行描述、状态及启停/卸载入口；宽度与市场同列卡片一致。

`contract-impact = none`：只调整 Desktop 卡片样式与布局，安装、启停、权限、API/Agent Host 和持久化边界均不变。


### 专家卡片与搜索布局（2026-10-16 用户调整）

2026-10-18 用户更新：从“扩展”菜单进入时默认选中“专家”；显式 `tab=skills` 链接仍打开
技能页，页签切换、搜索内容和独立滚动位置继续保留。专家卡片 hover / 内部键盘 focus
统一使用与技能卡片相同的 1px 品牌青柠描边、120ms 颜色过渡；保持原有底色和几何，
键盘操作控件仍保留可见中性焦点轮廓。该规则同时适用于真实专家和展示专家卡片。

“资深电商运营操盘手”的通用店铺图标替换为与相邻专家头像协调的彩色人物插画：
浅青柠背景、深色轮廓、运营顾问和包裹/图表意象。使用内置生图工具生成的本地资产，
通过 `jd-ops-expert` 映射复用于卡片和详情，尺寸与图片失败时的回退逻辑沿用原实现。

`contract-impact = none`：仅调整 Desktop 进程内默认视图、样式与本地展示素材；
Desktop/API/Agent Host 跨进程交互、Native IPC、权限和本地持久化/重放状态均无可观察变化。

专家列表采用三列等宽网格，16px 列间距；在 1180×760 最小桌面窗口下仍为三列，即使只有一个专家也只占一列。仅在列表容器不超过720px / 480px时降为两列 / 一列，兼容放大及更窄的容器。

卡片使用16px圆角、白色/暗色卡片表面与细弱边框，常态20px内边距（容器≤900px时16px）。头部使用48px本地头像，详情为64px；按受控expertId映射原有授权图片或本次生成的运营顾问插画。未映射或加载失败时回退32px业务图标与石墨底板：通用运营iconKey映射到Lucide店铺轮廓，其余有效iconKey保留，无效值回退人物轮廓。回退与操作图标统一通过YjIcon，界面颜色消费既有token。标题16/24/600，简介14/22/400单行省略，完整名称与简介可悬停查看，详情保留完整介绍和知识范围。

擅长标签使用12/18普通字重、浅中性底和4px圆角，允许换行及长词折行。底部使用12px元信息展示真实平台范围与资源状态；ready状态点只表达资源已准备，不代表执行权限。目录上方显示当前筛选结果数量和简短操作提示，不制造使用量、热度或模拟专家。

召唤操作移至卡片底部右侧，使用中性文字与方向图标；hover或内部键盘focus时显示，已选、忙碌、不可用与无悬停设备保持可见。操作始终占据原位置，出现时不会挤压标题或改变卡片几何；准备资源仍是独立操作，空间不足时底部换行。键盘焦点保持2px中性轮廓，卡片hover与内部键盘focus采用品牌青柠细边框，不改变底色、浮起或添加阴影。

搜索保持在技能/专家页签同一工具栏右侧，宽320px且不超过容器，含搜索图标和清除功能，仅专家页签显示；窄空间允许工具栏换行。搜索文字在页签切换时保留，身份范围变化时清空，筛选、空态和权限行为不变。异常、只读权限及未完成操作提示保留原有语义。

`contract-impact = none`：只涉及Desktop展示样式、文案与本地图标映射，不改变API/Host、原生权限、安装、召唤意图、会话或持久化边界。普通组件预览与交互回归不冒充原生执行链路或FEAT-158全量重新验收。

### 本地专家展示资料（2026-10-16）

用户指定的10位WorkBuddy本地单专家作为静态展示卡片加入既有网格；不纳入专家团。素材保留原头像和文字，使用易界字体、圆角、间距、亮暗主题。卡片底部有「展示」标识，打开独立详情弹窗；推荐问题为普通文本，无召唤/安装/跳转开发者网站等执行操作。开发者、版本等只显示真实来源字段，缺失使用量与市场ID不补写。

静态类型独立于真实可执行专家目录；原生目录不可用时仍可浏览和搜索静态资料，原真实专家保持既有权限与调用边界。详情支持内部滚动、Esc关闭、焦点返回，切换页签或离开页面时关闭，不把焦点返回旧页面。字段与来源见仓库 `docs/verification/workbuddy-expert-showcase-20261016.md`。


### 第一组专家真实接入（2026-10-16）

小红书爆款笔记策划、漫剧编剧与分镜师、跨境电商运营专家改由 Native 专家目录提供，静态展示清单只保留其余 7 位。名称、描述、快捷问题、资源和执行状态均取自 Native；旧目录或读取失败时不由静态内容补造这 3 位。原有资深电商运营操盘手保持原流程，完整目录为 4 位真实专家与 7 位展示专家。

真实卡片和详情用受控 expertId 映射显示前序已授权的本地头像；图片路径不进入 ExpertRef、安装请求或发送身份。无映射或图片加载失败时回退既有 iconKey，未知 iconKey 回退人物图标。卡片头像维持 48px、详情头像 64px，尺寸和颜色使用既有 token，三列布局不变。

资源准备、移除、当前会话选择与快捷问题继续复用既有组件和 composable。快捷问题只准备资源、选择专家并填入草稿，用户显式发送后才执行；「资源已准备」仍不代表连接器或外部业务可用。专家的实际能力范围由适配后的 Native 内容说明，不沿用展示快照的旧承诺。此处仅描述前端承接；完整跨仓分类及功能验收见元仓第一组接入记录，组件测试不代替真实模型与持久化验证。
