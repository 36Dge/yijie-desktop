# 经营分析 Pattern


## 文档状态

- 状态：Accepted
- 版本：1.0.0-final
- 适用仓库：`yijie-desktop`
- 适用技术栈：Tauri v2、Vue 3、Vite、TypeScript、Pinia、Vue Router、Naive UI、ECharts、Lucide
- 默认语言：中文

## 目标

定义店铺经营数据分析页面。

## 适用范围

适用于对应页面 pattern 的路由页面、业务组件、状态管理、接口接入和文案。

## 规范正文

经营分析页面由指标摘要、趋势图、商品表现、异常提醒、AI 解读和建议动作组成。先展示结论，再展示数据明细。

数据必须显示时间范围、同步状态和数据来源。AI 解读必须与实际指标对应，不能空泛建议。

## AI / Codex 必须遵守

- 新页面必须先匹配既有 pattern；没有匹配项时先补 pattern 文档。
- 不允许在页面中重新创造布局、状态和交互流程。
- 必须包含 loading、empty、error、permission denied 状态。
- 涉及 Agent 的页面必须展示过程和结果。

## 实现要求

页面文件放在 `src/pages/` 对应业务目录，复杂逻辑进入 `src/domain/` 或 composables。页面只负责组合组件和绑定状态，不承载复杂业务规则。

## 验收清单

- [ ] 页面结构符合 pattern。
- [ ] 主操作明确。
- [ ] 数据和状态完整。
- [ ] 风险/权限/错误已覆盖。
- [ ] 组件复用而非页面堆叠。

## 方案 2：经营总览与 AI 运营（2026-10-05）

本次用户已明确授权重新设计“我的店铺”的视觉布局和交互。方案 2 采用参考图中的多列经营看板、组合指标卡和图表密度，替代旧页面的信息结构；配色、字体、组件状态和可访问性仍遵循易界设计系统。方案 1 保留在 `src/pages/store/StoreLegacyPage.vue`，不注册路由、不提供页面入口；默认 `/store` 展示方案 2。

### 两个 Tab 的职责

| Tab | 用户问题 | 信息内容 |
| --- | --- | --- |
| 经营总览 | 店铺经营表现如何，哪些变化值得关注？ | 销售额与预估利润、销售/利润/订单趋势、目标进度、流量转化、商品与品类表现、广告效率、易界 AI 洞察及经营简报。 |
| AI 运营 | 易界发现了哪些机会，可以生成什么运营方案？ | 模拟收益与效率指标、AI 贡献趋势、广告提效/Listing 优化/口碑洞察机会、机会筛选、分析证据、分步骤生成过程、可阅读的方案结果与工作动态。 |

第二个 Tab 不使用库存分析。AI 建议必须关联具体模拟指标和证据；预计收益明确为演示估算，不描述为已确认的真实经营效果。

### 数据与交互边界

- `contract-impact = none`：改动限于 Desktop 的展示与本地临时交互，不改变 API、Agent Host、原生 IPC 或持久化契约；没有新增接口、原生命令或持久状态。页面视觉本身有用户可见变化。
- 数据由 `src/domain/store-dashboard.ts` 中的固定样本和确定性计算生成。店铺与时间范围选择联动更新经营指标、图表和商品数据；全部演示金额统一使用 USD，即使店铺标签为英国站或德国站，也不表示真实汇率换算。
- `src/composables/useStoreDashboard.ts` 维护页面内存状态。搜索、排序、分页、刷新、Tab 切换、抽屉与方案生成不访问后端；离开页面后不保留模拟执行记录。
- 导出只生成当前筛选商品的本地演示 CSV。它不是业务接口或店铺数据同步，也不改变应用持久状态。
- “模拟生成方案”展示三个步骤与具体文字结果。完成后可重新查看结果，并在 AI 工作动态中显示本次模拟完成记录；不提交商品、广告预算或店铺设置变更。
- 页面支持 ready、loading、empty、error、permission denied 的视觉演示与恢复入口；这些状态不代表已接入真实权限判断或网络错误处理。

### 视觉与可访问性

- 使用易界白色/石墨结构空间、青柠主操作及既有 chart tokens；领域图表组件通过 `createArtifactReportEChartsTheme` 解析主题，不暴露 ECharts 默认配色。
- 图表提供指标、单位、时间范围、Tooltip、交互图例和可展开数据表；图表点击可打开明细。可视化结论与表格信息共同承载内容。
- Tabs、筛选、表格操作和抽屉需可键盘访问并显示焦点；图标按钮提供可访问名称，长数字使用一致的单位与格式。
- 宽屏采用分组卡片和主次图表，最小窗口按可用空间重排，不挤压工具栏。亮色、暗色和 `1180×760` 窗口须单独检查；动画尊重 reduced motion。
- 验证记录与明确未执行的检查见仓库文档 `docs/store-dashboard-plan-2.md`，未完成的视觉或原生检查不得标记为通过。

### 方案 2 视觉修订（2026-10-05）

依据用户对首版的视觉反馈，本次局部收敛风格并加强 AI 运营的信息密度：

- 活跃店铺页面不使用星芒、魔法、机器人类图标作为 AI 装饰；通过清晰标题、业务名称、数据关系与状态表达智能运营能力。商品表取消彩色图标底块，以中性序号建立阅读顺序。
- 经营总览上部维持既有布局。下部「销售来源」使用青柠、石墨、灰色的领域配色，并增加渠道转化效率；「商品表现」增加销售额与环比的散点分布，点面积关联订单量，支持打开对应商品详情。
- AI 运营将指标变化、优化效果、机会优先级、评价主题、能力覆盖和行动场景组合展示。青柠用于重点数据，石墨与中性线条用于对照，不用无业务含义的渐变、装饰图标或多色卡片制造视觉层级。
- 从方案 1 精选广告诊断、差评归因、流量与竞品等场景，将其转化为可筛选的分析入口；每个入口须有具体模拟证据、执行步骤和可阅读结果。旧方案仍隐藏，未恢复旧页面布局。
- 局部领域配色不修改全局图表主题，也不影响其他页面。依旧为纯前端模拟，`contract-impact = none`，无 API、原生或持久化变化。
