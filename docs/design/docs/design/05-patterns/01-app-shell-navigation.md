# App Shell 与导航 Pattern


## 文档状态

- 状态：Accepted
- 版本：2.2.0
- 最后更新：2026-09-05
- 适用仓库：`yijie-desktop`
- 适用技术栈：Tauri v2、Vue 3、Vite、TypeScript、Pinia、Vue Router、Naive UI、ECharts、Lucide
- 默认语言：中文

## 目标

定义易界桌面端全局应用壳、主导航和工作区结构。

## 适用范围

适用于对应页面 pattern 的路由页面、业务组件、状态管理、接口接入和文案。

> FEAT-130：主导航顺序、任务记录静态分组、`/tasks` 页面移除及独立滚动树以
> `15-feat-130-sidebar-layout.md` 为准；本文其余规则继续有效。

## 规范正文

App Shell 由左侧导航和主工作区组成；顶部状态区与右侧上下文面板由具体页面 pattern 决定，不再作为所有路由的必选区域。

### 色彩与品牌

App Shell、导航与主内容的亮色结构背景均为纯白，主要文字为石墨；使用留白、既有间距与细中性边框划分区域。青柠用于主操作和局部选中强调，不对整页或业务区块铺绿底。暗色使用中性石墨主题层级，品牌区必须选择对应的新商品包裹 / YJ SVG 变体。此规则覆盖旧页面截图的配色，不改变下述结构与行为。

### `/chat` 新建任务入口态

- 已登录用户进入主应用时，默认路由保持 `/chat`。
- `/chat` 没有活跃会话时使用“新建任务入口态”，不展示租户、店铺、同步、Runtime 状态和用户入口。
- 入口态不展示 Chat 会话列表和右侧上下文面板；主工作区使用居中的单列布局。
- 未来进入活跃会话后，页面再切换到 Chat 工作区 Pattern。本次入口态不得伪装已具备真实任务提交或会话能力。

### 侧栏结构

侧栏首次启动默认使用 240px 展开模式，并支持 72px 图标模式。导航从上到下分为：

1. 品牌区：批准 Logo 和“易界”品牌文案。
2. 任务组：
   - “新建任务”，路由 `/chat`。
   - “任务记录”按 FEAT-130 作为项目与对话树分组，不与“工作流”或“定时任务”合并。
3. 业务模块组：“我的店铺”“工作流”“定时任务”“插件”“资料库”。“工作流”由 FEAT-151 使用 `/workflows`；模块尚未实现时显示为禁用状态，不创建占位路由。
4. 底部辅助区：“设置”，路由 `/settings`，固定在侧栏底部。

无权限模块不渲染。前端隐藏只负责呈现，不能替代服务端资源授权和直接深链检查。

### 展开与收起

- 收起按钮固定在侧栏右边界，并与品牌区垂直居中；侧栏宽度切换后按钮仍位于同一语义位置。
- 按钮使用批准的面板收起/展开图标，命中区域不小于 32 × 32px。
- 展开态显示图标和文案；收起态仅显示图标，并为可用入口提供 tooltip。
- 按钮提供动态 `aria-label`：“收起侧栏”或“展开侧栏”，并用 `aria-expanded` 表达当前状态。
- 收起状态作为普通本地 UI 偏好跨路由和应用重启保留，不包含用户、租户或业务数据。首次启动、值缺失、值损坏或读取失败时回退到 240px 展开模式。

本地偏好格式：

| 字段 | 规范 |
|---|---|
| 存储 | Desktop WebView 的普通 Web Storage；不得使用 Keychain 或安全存储 |
| Key | `yijie.desktop.ui.sidebar.v1` |
| Value | 字符串枚举：`expanded` 或 `collapsed` |
| 默认值 | `expanded` |
| 未知/损坏值 | 忽略并回退到 `expanded` |
| 兼容与回滚 | 旧版本忽略新 key；回滚后遗留 key 无业务或安全副作用 |

### 导航状态

- 当前路由项使用 `selected/active` 状态，并同步 `aria-current="page"`。
- 可用入口由 Vue Router 导航。
- 未实现但有权限的入口使用 `disabled` 状态：不触发路由、不响应点击或快捷键，并提供“即将开放”的可见或辅助说明。
- 无权限入口使用 `hidden` 状态：不出现在视觉树和可访问性树中。

主工作区根据页面类型切换：新建任务入口态使用单列首页，活跃 Chat 使用会话工作区，数据页使用 PageHeader + MetricCards + Table/Chart，任务页使用 Timeline + Result + Trace。右侧面板用于上下文、审批、详情，不作为主导航替代。

## AI / Codex 必须遵守

- 新页面必须先匹配既有 pattern；没有匹配项时先补 pattern 文档。
- 不允许在页面中重新创造布局、状态和交互流程。
- 必须包含 loading、empty、error、permission denied 状态。
- 涉及 Agent 的页面必须展示过程和结果。
- 不得为禁用导航创建看似可用的假页面，也不得把无权限隐藏当成授权控制。

## 实现要求

页面文件放在 `src/pages/` 对应业务目录，复杂逻辑进入 `src/domain/` 或 composables。页面只负责组合组件和绑定状态，不承载复杂业务规则。

- [ ] 收起偏好可恢复，异常值安全回退到展开模式。
