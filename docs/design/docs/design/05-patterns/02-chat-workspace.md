- 状态：Accepted
- 版本：1.1.0

- 输入、项目选择、审批入口等任何首页操作立即获得响应；动画从当前姿态直接向终态插值，160ms 内收尾，不快放剩余时间线。切页后的标题自动聚焦保留无障碍语义，不触发动画收尾；键盘聚焦输入框或按钮等控件时才收尾。窗口隐藏、开启减少动态效果或组件卸载会取消动画；完成后没有持续 RAF。

- 页面主标题精确显示“易界AI”。

  1. “搜索热销商品关键词，发现下一个爆款…”
  2. “输入目标市场，获取本地化选品建议…”
  3. “查询物流方案，对比各国时效与运费…”
  4. “粘贴商品链接，一键分析竞品数据…”
  5. “输入店铺名称，诊断运营健康度…”

#### 每轮耗时（2026-09-29）

参考对话用时视频，在本轮用户气泡下方、首条模型/工具内容上方，显示左对齐的次要文字“已处理 N秒”，下方使用仅覆盖正文列的细分隔线。当前运行轮次每秒刷新；成功完成后显示“已完成 Ns”，以总秒数展示；失败、中断及未知状态仍显示原来的“用时”文案，不能因存在耗时误标成功。暂缺原生计时的记录不占空行，不显示虚构零值；真正的原生零耗时在完成状态显示“已完成 0s”。有可折叠过程记录时，时间行附带右/下箭头，可点击或使用 Enter、Space 展开/收起整轮过程；没有过程记录时仅显示时间，不显示空折叠入口。没有原生耗时但有过程记录时显示“处理过程”。时间不逐秒进行 aria-live 播报。

展开按原始顺序显示明确的 commentary、推理摘要/记录、命令与工具记录，以及已有执行计划；用户输入、final_answer、缺省或未知 phase 的普通回答、生成内容和未知类型保持独立可见。过程说明采用无框正文，工具记录采用次要文字的紧凑行并保留原详情入口、参数安全投影及复制能力。待审批、决策提交/核对/错误、失败/拒绝/未完整结束、内容不可用等项目与轮次通知不会随过程折叠而隐藏。

已结束及非实时历史默认收起，确认实时运行中的轮次默认展开。用户选择、过程区内的焦点和鼠标操作会保留当前展开状态；后续秒数变化、流式内容更新和完成事件不会覆盖用户选择。未手动操作的实时轮次在第一段回答正文开始显示时自动收起，最迟在轮次结束时收起；缺省 phase 的普通回答遵循同一展示规则，但不改变其原始阶段。交互状态仅在当前组件内存中，切换为另一轮时重新初始化。触发按钮用 aria-expanded 与稳定的 aria-controls 关联全部过程条目；收起后条目退出可访问树和键盘焦点顺序。条目 DOM 保持，避免流式正文或工具详情因折叠而重新挂载。

本次整轮展开交互的 `contract-impact = none`：只消费上一版已有投影、phase、耗时和权限事实；Desktop/API/Host 跨进程接口、原生模型机制及本地持久状态均无变化。

开始和最终耗时复用 Codex 原生字段，最终耗时不由前端计算，不影响运行状态、正文、复制、审批或输入框。时间行采用现有 body 字号（14px，比原 caption 增大 2px）、secondary 文字和 subtle 边框 token，亮暗主题与 1180×760 窗口均遵循同一正文列宽。

`contract-impact = additive`：增加 Desktop 私有只读计时查询，复用已固定的 Host 原生计时接口及 `read_sessions` 权限；公共协议、Codex 计时机制和本地持久状态不变。完整来源与兼容边界见 `docs/chat-native-conversation.md`。

#### 模型回答正文（2026-09-27）

最终回答和未分类模型消息采用无外框、无底色、始终展开的正文布局。2026-09-29 阶段兼容调整：两者不再显示助手图标和可见的“模型回答”标题，仅保留无障碍名称；移除回答右侧重复的“已完成”状态及其空标题行，正常流式回答也不显示右侧“进行中”，异常和进度未确认提示继续保留；正文和复制操作保持。缺少可识别阶段本身不再展示警告图标、“未分类模型消息”或“未将其视为最终回答”说明。整条模型消息的底部复制操作只在该消息状态确认为 completed 后显示；started、streaming、incomplete 时不显示，也不因 busy=false 或整轮结束推定消息完成。用户消息与代码片段的既有复制行为不变。过程记录、工具、审批和结构化结果卡保持原有布局。

问题来源与方案：Runtime 的 `phase` 是可选字段，部分模型及历史记录不提供它；Codex CLI 对此保留旧模型兼容显示。Desktop 原先把缺省阶段映射为可见警告，导致正常正文看起来异常。现在只调整显示标签、图标和说明，内部 `assistant_unclassified`、原始 phase、消息及轮次状态均保持原值，不通过消息完成事件伪造 `final_answer` 或整轮完成。明确的 `commentary` 仍为“处理过程”，`final_answer` 仍为明确最终回答；内容不完整、不可用、失败和中断提示继续由各自真实字段决定。审批内容保护及复制策略不变；结构化草案继续走校验后的专用展示，并保留“草案以校验结果为准”说明。

正文按 Markdown 展示标题、强调、删除线、段落、换行、分隔线、引用、嵌套列表、表格和代码；标题字级和间距使用现有 yijie tokens。用户原始输入及推理记录仍采用原文展示。格式化只作用于展示，复制继续获取原始 Markdown；不执行内嵌 HTML、不改变链接的现有非跳转行为，也不把普通 Markdown 自动生成新的图表。

`contract-impact = none`：只改变 Desktop 展示与前端 Markdown 排版；Desktop/API/Agent Host 跨进程交互、权限、原生阶段语义和本地持久状态不变。

#### FEAT-155 单次执行与独立重跑（4C-3）

立即运行支持当前开启、暂停及已完成计划，执行前明确一次/最长10分钟许可，自动授权和计划状态独立。记录中的重新执行先只读展示原运行与当前已保存配置差异；当前配置无变化也明确创建新运行，旧历史不覆盖。未执行槽不冒充run，已删除计划/失效目标有具体禁用原因；已完成once不因手动动作复活为自动计划。

重跑审阅不准备执行服务，确认时才显式准备并申请本次许可。默认焦点取消，长文本内部滚动，亮暗与1180×760最小窗口/键盘可用。grant与run持稳定请求ID；回执未知只查证或明确原请求重试，不换ID续额；受理、原生终态与业务结果分开，定位新run对应的对话轮次。单次期间自动到点仍按原忙碌跳过规则处理，不排队补跑。

#### FEAT-155 有限自动运行（4C-2）

计划创建后保持暂停。管理卡片的启用/重新确认打开单一确认弹窗，展示内容、运行于、目录语义、Ask、时区与下次时间；默认1次与下次时间后10分钟截止，允许明确调整有限次数/期限，不提供无限授权。截止采用设备时区并显示实际时区名称，下一次时间按计划固定时区展示。默认焦点取消，提交有局部loading；未知保留原请求，只读查证或显式同请求重试，不能自动续额。原生预览变化后重新审阅。

卡片真实区分已启用、暂停/需确认和完成；展示授权到期、额度、未知结果、目标/资源不可用等原因。服务未就绪可显式重新准备，不把管理读取变成启动操作。暂停不会假终止已开始的运行；查看结果沿原运行与对应聊天轮次。仅在App运行且设备清醒时自动执行，正常重开恢复未来，离线不补跑；当前独立重跑、电源和应用内更新不在本批开放。采用既有Naive/Yj组件与2.1.0 tokens，长确认内容内部滚动、亮暗与最小窗口可用。

#### FEAT-155 对话创建定时计划（4B）

管理页“通过对话创建”回到既有新任务输入框，按当前scope一次性预填引导词，等待用户发送。已有输入默认保留，切换需确认；只交接明确输入的文本，不自动复制会话历史、附件或目录。新任务入口的草案模式提示“确认后才会保存”，隐藏普通项目、附件和权限切换操作，使用原ChatComposer和原生聊天展示。

新建定时任务的聊天入口在尚无草案结果时只展示原 ChatComposer；草案候选、待查证请求、错误或授权恢复确有内容时才展示草案面板。离开这一入口不再因自动预填模板弹出通用“未发送文字”确认；当前账号与授权版本范围内改过的文字暂存在应用内，下次通过管理页入口返回时恢复。普通聊天的未发送文字确认和待查证草案请求的离开保护继续生效。

`contract-impact = none`：仅调整 Desktop 页面展示和内存中的输入交接；Desktop/API/Agent Host 跨进程接口、权限与本地持久状态均无可观察变化。

已有会话用途由native的scoped只读查询决定，不能由URL、名称或模型话术推断。普通聊天与受限草案使用各自既有发送路径；缺少用途证据时禁止误发。草案最终结果由native校验，澄清问题和候选摘要使用中文卡片呈现，不要求用户阅读内部JSON。

用户审阅候选时复用管理表单，明确时间/时区及运行目标。模型给出的已有聊天名称只作提示，实际关联必须从授权列表选择。确认仅保存暂停计划，结果不明先按原请求/source查证；重开和刷新不重发。已确认计划可按真实ID返回管理页查看，删除来源不伪造或复活计划。

候选卡在聊天页底部有界滚动，长内容不挤掉输入或确认操作；表单内部滚动，默认安全取消/继续编辑。亮暗主题、1180×760外框及键盘操作保持既有规范。计划执行启用、重跑、唤醒与通知不在4B页面开放。

Chat 工作区由会话列表、消息区、输入区和右侧上下文面板组成。消息区必须区分用户消息、AI 消息、工具调用、审批卡片、结果卡片。输入区支持文本、附件、商品链接、店铺上下文选择。

AI 回答不能只有自然语言，还应在需要时附带结构化结果卡。长任务应转为 Agent 任务流，不在单条消息里无限滚动。

活跃会话态不在 FEAT-124 的实现范围内；不得用入口态本地输入模拟真实会话创建。
