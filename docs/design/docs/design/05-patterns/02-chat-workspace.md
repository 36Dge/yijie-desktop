# Chat 工作区 Pattern

当前审批只展示待处理请求。终端卡位于输入框上方，优先展示原生理由、完整命令和可展开的工作目录；浅色/深色的中性主按钮默认为「允许一次」。只有原生请求带有可审阅的命令前缀才显示下拉入口，菜单展示「允许一次」「允许类似命令」及确切前缀。拒绝、断线、提交中、失败核对使用原审批接口。审批卡取得焦点时 Enter 允许一次、Esc 拒绝；在菜单中 Esc 只收起菜单。用户的选择不会变成聊天记录，工具执行结果仍按原轮次展示。

## 规范正文

### 权限续期的页面连续性（2026-11-09）

5分钟是授权有效期，不是页面生命周期。同身份、同租户、同授权版本和完整能力集合的
正常续期保持当前contextId、订阅、消息、附件、预览、草稿、展开选择、输入焦点及滚动
位置，不清空页面或进入整页loading。原生在旧上下文到期前重新核实权限并续期；临时
不可用只在原有效期内重试，真实拒绝、到期、退出或切换身份继续执行原有撤销流程。
既有显式重绑的问答重新确认保护保留。私有IPC、安全边界与验证记录见
仓库 `docs/chat-authority-renewal.md`。

### 执行轨迹活动分组（2026-11-03 复审修复）

2026-11-04 用户确认：`warning + runtime_notice` 的通用运行提示不在前端显示，包含轮次和对话通知两个入口，隐藏后不保留空容器。原通知继续保存在事实与会话数据中；明确原因的提示、错误及重试状态仍保留。`error + runtime_notice` 显示已有错误/重试状态，不显示无详情兜底句或空展开按钮。此变更仅为阅读层过滤，`contract-impact = none`，不改变 API/IPC、执行语义或持久化内容。

2026-11-04 思考摘要修复：普通 reasoning 仍不插入工具活动列表，但每轮有一个独立、稳定的“思考摘要”入口，只消费原生已允许展示的 summary 块。当前思考优先使用最后可读摘要的 Markdown 标题或单独粗体段，缺少标题时使用最后可读行；标题限长，内容不裁剪或改写成 commentary。同一 Item 的标题及时更新，切换 Item 复用 1 秒稳定化；首条摘要和已结束状态立即更新。

摘要入口位于耗时下方，不作为工具分组边界。默认收起，点击后按原生 Item/块顺序查看，保留原身份、重复摘要与阅读位置；工具过程的展开选择不控制摘要。正文开始时停止当前思考动画，未操作的摘要保持收起，用户已展开的摘要保持可读。切换会话或重新挂载后默认收起，但仍能从既有记录展开。只有空摘要/原始 content 时不伪造摘要入口；已有诊断仍沿异常入口展示。历史不播放实时状态，已收到的摘要在展开时立即可读，不重新播放打字动画。

有可读当前摘要时，它独占思考状态；工具运行、原生重试、公开消息及正文优先，工具组不重复显示同一个思考提示。运行中的单项工具组保持容器，避免摘要接管状态时移除用户正在操作的组头。全链路仍复用 Native6/SSE13/IPC6/format6；本次 `contract-impact = none`，只改 Desktop 进程内阅读投影和组件，API/IPC/原生执行、phase、权限与持久化读写语义均不变，不清库、不迁移。

用户批准 FEAT-167，以提供的 Codex 视频及 v2 复审为目标。此节覆盖下文逐条“深度思考”、第 N 次搜索和重复系统进度的旧规则。原生 Item 是事实；ActivityEntry 是前端派生行；连续活动组是阅读容器，三者不等同。普通 reasoning 保留在事实层，不占工具列表行、不建立分组边界。显式诊断仍有可查看入口；当前思考只在一个状态位出现。

公开 commentary 保留原文并分段；unknown phase 原值不变。最后一条可读未知阶段回答在运行中和终态都保持可见；只有存在后续可读回答并观察到工具继续，前一条未知消息才可折叠进过程。末尾可读 commentary 作为阅读候选保持外显，原始 phase 仍为 commentary，不据此判定正式终答。原生 commandActions 可派生多个独立行，沿用父 Item 状态、输出和审批，只计一次调用。行标题使用 Host 受限安全预览、结构化动作目标或可信工具标题，缺失时诚实兜底；other 网页动作不叫搜索。

连续命令、工具、网页活动默认折叠；组锚点采用首个工具事实身份，不受普通/空 reasoning 变化影响。已结束单项组可直接显示一条活动；已有用户展开选择时保持原容器。单个命令补齐一个动作时沿用父身份，多动作才使用父身份与原始动作索引组合。只有最新且没有被公开消息关闭的组显示当前动作或思考，其他组显示摘要。组头按来源与动作类别组合，调用数、命令动作数、检索来源数单位分开；同一头部身份的文字立即更新，身份切换按 1 秒窗口稳定化，完成摘要立即替换。此延迟不影响事件、保存或原生执行。

整轮耗时可折叠普通过程，当前实时轮在显式最终正文开始前默认展开，历史默认收起。组、单项详情独立控制；用户点击、焦点、选区后的选择优先。组内列表复用短滚动条的网格容器，最长320px，正常增量不抢用户阅读位置。计划单独呈现，未完成步骤不会随轮次结束勾选。失败、待审批及决策瞬态仍在折叠外；重试只读原生 willRetry，连续等价通知仅在阅读层折叠，原始通知保留。

内容可用性与执行资格分开：正常输出等待及参数隐藏不使可信 inProgress 失活；真实流缺口、未知诊断和冷历史仍不冒充实时。所有查看操作不派发命令、不重放任务。

保持 Native6/SSE13/IPC6/record6；复审修复保留现有新格式会话，不再清库，不新增数据库迁移。前轮已批准的旧V4/SSE11退役保持；凭据、配置、技能资源与工作空间文件保留，不含diff。实际证据见 FEAT-167 复审修复报告。

### 任务标题与完成标记（2026-11-02）

顶部任务标题按用户要求从18px减至16px，复用 `--yj-font-size-card-title`；既有行高、字重、省略及标题区高度保持。此字号调整的 `contract-impact = none`：Desktop/API/Agent Host跨进程交互、Native IPC与本地持久状态均不变。

任务标题区不显示底部分割线或重复的“已完成”等轮次状态。没有工作空间及草案信息时不保留空的副标题行；已有工作空间、定时任务草案说明和异常/恢复提示继续显示。对话内的每轮耗时、过程状态以及读屏状态播报保留。最近一轮尚未查看的完成信息由左侧任务名称右侧的6px正文链接同色色点表达，点击任务后清除并定位到最新一轮的起始位置，具体生命周期见[主导航与任务记录](./15-feat-130-sidebar-layout.md)。

#### 模型回答正文（2026-09-27）

最终回答和未分类模型消息采用无外框、无底色、始终展开的正文布局。2026-09-29 阶段兼容调整：两者不再显示助手图标和可见的“模型回答”标题，仅保留无障碍名称；移除回答右侧重复的“已完成”状态及其空标题行，正常流式回答也不显示右侧“进行中”，异常和进度未确认提示继续保留；正文和复制操作保持。缺少可识别阶段本身不再展示警告图标、“未分类模型消息”或“未将其视为最终回答”说明。整条模型消息的底部复制操作只在该消息状态确认为 completed 后显示；started、streaming、incomplete 时不显示，也不因 busy=false 或整轮结束推定消息完成。用户消息与代码片段的既有复制行为不变。过程记录、工具、审批和结构化结果卡保持原有布局。

#### FEAT-155 单次执行与独立重跑（4C-3）

立即运行支持当前开启、暂停及已完成计划，执行前明确一次/最长10分钟许可，自动授权和计划状态独立。记录中的重新执行先只读展示原运行与当前已保存配置差异；当前配置无变化也明确创建新运行，旧历史不覆盖。未执行槽不冒充run，已删除计划/失效目标有具体禁用原因；已完成once不因手动动作复活为自动计划。

重跑审阅不准备执行服务，确认时才显式准备并申请本次许可。默认焦点取消，长文本内部滚动，亮暗与1180×760最小窗口/键盘可用。grant与run持稳定请求ID；回执未知只查证或明确原请求重试，不换ID续额；受理、原生终态与业务结果分开，定位新run对应的对话轮次。单次期间自动到点仍按原忙碌跳过规则处理，不排队补跑。

#### FEAT-155 有限自动运行（4C-2）

计划创建后保持暂停。管理卡片的启用/重新确认打开单一确认弹窗，展示内容、运行于、目录语义、Ask、时区与下次时间；默认1次与下次时间后10分钟截止，允许明确调整有限次数/期限，不提供无限授权。截止采用设备时区并显示实际时区名称，下一次时间按计划固定时区展示。默认焦点取消，提交有局部loading；未知保留原请求，只读查证或显式同请求重试，不能自动续额。原生预览变化后重新审阅。

卡片真实区分已启用、暂停/需确认和完成；展示授权到期、额度、未知结果、目标/资源不可用等原因。服务未就绪可显式重新准备，不把管理读取变成启动操作。暂停不会假终止已开始的运行；查看结果沿原运行与对应聊天轮次。仅在App运行且设备清醒时自动执行，正常重开恢复未来，离线不补跑；当前独立重跑、电源和应用内更新不在本批开放。采用既有Naive/Yj组件与2.1.0 tokens，长确认内容内部滚动、亮暗与最小窗口可用。

#### FEAT-155 对话创建定时计划（4B）

管理页“通过对话创建”回到既有新任务输入框，按当前scope一次性预填引导词，等待用户发送。已有输入默认保留，切换需确认；只交接明确输入的文本，不自动复制会话历史、附件或目录。新任务入口的草案模式提示“确认后才会保存”，隐藏普通项目、附件和权限切换操作，使用原ChatComposer和原生聊天展示。

新建定时任务的聊天入口在尚无草案结果时只展示原 ChatComposer；草案候选、待查证请求、错误或授权恢复确有内容时才展示草案面板。离开这一入口不再因自动预填模板弹出通用“未发送文字”确认；当前账号与授权版本范围内改过的文字暂存在应用内，下次通过管理页入口返回时恢复。普通聊天的未发送文字确认和待查证草案请求的离开保护继续生效。

`contract-impact = none`：仅调整 Desktop 页面展示和内存中的输入交接；Desktop/API/Agent Host 跨进程接口、权限与本地持久状态均无可观察变化。

已有会话用途由native的scoped只读查询决定，不能由URL、名称或模型话术推断。普通聊天与受限草案使用各自既有发送路径；缺少用途证据时禁止误发。草案最终结果由native校验，澄清问题和候选摘要使用中文卡片呈现，不要求用户阅读内部JSON。

用户审阅候选时复用管理表单，明确时间/时区及运行目标。模型给出的已有聊天名称只作提示，实际关联必须从授权列表选择。确认仅保存暂停计划，结果不明先按原请求/source查证；重开和刷新不重发。已确认计划可按真实ID返回管理页查看，删除来源不伪造或复活计划。

候选卡在聊天页底部有界滚动，长内容不挤掉输入或确认操作；表单内部滚动，默认安全取消/继续编辑。亮暗主题、1180×760外框及键盘操作保持既有规范。计划执行启用、重跑、唤醒与通知不在4B页面开放。

Chat 工作区由会话列表、消息区、输入区和右侧上下文面板组成。消息区必须区分用户消息、AI 消息、工具调用、审批卡片、结果卡片。输入区支持文本、附件、商品链接、店铺上下文选择。

AI 回答不能只有自然语言，还应在需要时附带结构化结果卡。长任务应转为 Agent 任务流，不在单条消息里无限滚动。

活跃会话态不在 FEAT-124 的实现范围内；不得用入口态本地输入模拟真实会话创建。
