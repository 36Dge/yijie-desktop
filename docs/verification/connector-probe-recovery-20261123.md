## 恢复为何停住

1. 管理页开关读取安装记录的 `desiredEnabled`。聊天弹窗的候选项还要求当前 Host 确认 `effectiveEnabled`，实际选用还检查使用权限和连接就绪状态。[管理开关](../../src/components/connectors/ConnectorInstalledList.vue) · [聊天候选与选用](../../src/components/chat/ChatConnectorControl.vue)
2. Sorftime 最后一条启用检查属于旧 Host 和旧桌面进程。旧实现看到未完成操作就略过启动复查。查询原回执又要求原 Host、进程和权限版本匹配。后续启动因此一直读到同一条处理中记录。[启动恢复](../../src-tauri/src/chat/connectors/startup.rs) · [Host 回执校验](../../src-tauri/src/chat/connectors/provider.rs)
3. 检查处于起始阶段时，授权状态可能仍为未知。原启动逻辑还要求已配置且已授权，即使单独清除旧操作也可能错过复查。同一实例的自动查询另有五分钟或 120 次的上限，达到上限后，原来仅刷新快照也无法读到迟到的结果。[连接器状态存储](../../src-tauri/src/chat/connectors/store.rs) · [前端回执观察](../../src/stores/market-connectors.store.ts)

## 修复行为

- 持有当前范围的连接器管理权限时，桌面端在同一数据库事务中核对安装、代际、版本、凭据引用及检查归属。已经失去建立当前连接资格的旧启用检查以 `failed / execution_unavailable` 结束。最后一次供应商观察留存，旧回执可重复读取，迟到结果不能改写终态。
- 已成功启用过的安装使用保存的绑定发起新的元数据检查。只有新实例实际验证工具后，该项才能加入对话。当前实例仍在处理的检查继续使用原操作编号。首次启用尚未成功的安装保留关闭状态，用户可以在详情中重新检查现有绑定。
- 连接器授权、配置、停用和卸载继续使用各自的原操作流程。打开弹窗或主动刷新可以恢复对一笔慢启用操作的限次查询。选择连接器本身不发送聊天或供应商业务请求。
- `contract-impact = semantic`。变化限于桌面端对旧检查的本地恢复，沿用现有 Provider 协议、状态枚举及 SQLCipher 表。旧客户端可以读取已结束和新建的标准回执。回滚客户端会恢复旧的处理逻辑，旧版本遇到下一笔中断检查仍可能卡住。
