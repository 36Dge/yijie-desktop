# 图片与视频标题、ID 展示调整

用户要求移除对话流中的产物 ID 和媒体标题，在查看器中显示根据需求生成的名称及
扩展名，并将相同规则应用到视频。

`contract-impact=none`：本次只改变 Desktop 的呈现副本和组件属性；继续使用现有
Native/Host 产物身份、权限、MIME 与预览/保存接口，消息与产物持久数据不改写。
未修改 Host、Runtime、源契约或二进制，也未重新生成媒体。

## 实现

- 原图片固定名称为 `generated-image`，视频为 `生成的视频.mp4`；模型还可能把回执
  中的 ID 写进助手回答。现在以当前 authority 解析的媒体引用为范围，过滤助手正文
  中已关联媒体的技术 ID 标注，并保留原始历史和用于操作的 ID。
- 图片不再渲染可见 figcaption；视频就绪缩略图原本无标题，生成/失败卡片也去掉
  文件名。无障碍标签及查看器仍可读取名称。
- 有具体名称时保留；通用或纯 UUID 名称根据本轮用户需求提取主题及短场景描述。
  「重新生成一张图片」等明确重试可沿用此前媒体需求。例如本轮果汁提示词得到
  `冰镇气泡果汁-动态飞溅摄影.jpg`；是否使用 jpg/png/mp4 由实际媒体格式决定。
- 这是展示标题生成，不是额外模型推理或磁盘重命名。缺少可用需求和具体名称时只
  使用「图片/视频」类型名，不虚构内容。Native 保存窗口继续使用原有保存协议。
- 查看器复用既有文件名拆分函数，标题主体可省略，扩展名不被省略或挤入操作按钮。
- 文案过滤不会删除用户输入、普通文件或无关 UUID。只含 ID 的代码块可隐藏；实际
  代码及其格式保留。只生成前端副本，不回写 Runtime 历史。
