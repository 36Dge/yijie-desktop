# 对话定位与图片交互修复

用户要求修复：继续发送后的消息位置、已交付图片下方的通用等待提示、查看器关闭后的
对话滚动，以及图片操作三点按钮进入 Tab 顺序的问题。

`contract-impact=none`：仅改变前端定位、派生展示和焦点行为。继续复用原有本地接收
回执、Native Artifact authority、图片预览/释放接口、Runtime 轮次状态与通知；
没有修改 IPC、Host/Runtime、存储或重放格式。此前凭据及工作空间按钮改动保持。

## 改动

1. 原发送处理在一次 Vue tick 后直接滚到底部，但对话投影另有呈现帧，新轮次可能还未
   出现在 DOM。现在保存明确 session/turn/context 的定位意图，目标真正渲染后才定位。
   新轮次按可见高度及滚动留白预留最小高度，使新消息完整进入视口；保留输入焦点，
   后续仍可自动跟随，向上阅读会暂停跟随。尺寸调整、下一次提交和卸载会更新/释放留白。
2. 通用等待提示原先不读取已经呈现的 Artifact 状态。现在仅使用当前 authority 下
   `ready` 的产物来隐藏「等待模型继续输出」。未就绪或失去 authority 不算交付；
   审批、明确重试和推理状态继续按原事实展示，轮次不会被前端改成 completed。
3. 已安装弹窗库本身使用 `preventScroll` 归还焦点，静态已完成图片的原浏览器场景
   没有复现跳动；原应用仍缺少查看前阅读位置的保存。现在在打开时记录图片相对滚动
   容器的位置，关闭动画完成、原图片回到内联位置后恢复。换算 CSS zoom，并核对
   context/session/turn/artifact，避免旧窗口恢复到另一个任务。查看期间正常新增的
   回复不会把原图片带离阅读位置。
4. 图片三点按钮设为 `tabindex=-1`，鼠标菜单和 tooltip 保留；键盘可在图片上按
   Shift+F10 打开原菜单。菜单关闭后回到图片预览入口，继续保留查看器的焦点约束。
