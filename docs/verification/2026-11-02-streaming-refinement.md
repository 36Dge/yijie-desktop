## 发现与调整

参考视频中的新字持续从浅色变为正常文字，已经显示的正文不反复闪动。原实现要求积压在 160ms 内追齐，终态进一步压到 120ms；240ms 淡入使用快速趋近终值的通用缓动，大批文本到达时容易迅速冲出多行。

- 按时间积累字素预算，常规约 40 字素/秒，积压时平缓加速至最多 72 字素/秒。保留小数预算，使 30/60/120Hz 屏幕与细小数据包具有相近速度。首个字素不额外等待一批缓冲；单帧最多计入 50ms，长帧恢复不跳过整段。
- 新增专用 `--yj-motion-chat-stream-fade: 600ms`，采用线性 0.12 → 1 淡入。只作用于新字，保持可见的浅色尾部；成功完成不压缩剩余展示时间，也不清掉尚未结束的淡入。
- Markdown 补齐表格或代码围栏时，如果修订仅发生在尚未显示的尾部，保留当前显示位置。此前这个分支会把队列直接展开；浏览器真实组件回归复现并验证了修复。
- 历史、隐藏窗口、减少动态效果、强制颜色模式及失败/中断保持即时显示；文字选择期间暂停，释放后继续均匀推进。已显示正文发生真实修订时仍即时采用修订。跨批次补齐的 emoji 保持在同一字素 span。

北京先录制原效果，再用相同提问验证调整；苏州使用简介、三条列表和两列表格，随后复测格式补齐；南京在最终代码上验证简介与三条特色。真实响应内容由模型生成，前后两次回答及上游耗时不同，不能把这些数据当作同一响应的严格性能基准。
