# 多任务媒体交互复查

范围：连续切换多个对话、图片/视频快速关闭重开、刷新期间切换与关闭、关闭后的播放状态，以及缓存任务隔离。

`contract-impact = none`：只改变前端状态、DOM 生命周期和内存缓存调度。Desktop IPC、API/Agent Host、
原生权限、两视频句柄预算、持久化及重放语义不变。沿用既有媒体客户端，没有增加依赖、原生命令或跨仓修改。

## 发现与修复

| 问题 | 修复及证据 |
| --- | --- |
| `play()` 已发出但晚到时，关闭或刷新后的旧播放器可能恢复播放；原测试只检查 pause 被调用 | 用实际 paused 状态模型补充回归，修复前复现。播放事件和 Promise 收尾均检查当前显示者、媒体实例、授权及阶段；旧任务暂停，不误停已合法重开的窗口 |
| 刷新排队时，旧视频在等待其他解码期间仍会播放 | 刷新意图立即暂停，加载阶段禁止迟到播放；定向用例验证队列未完成时已 paused=true |
| 图片刷新加载层盖住整张旧图 | 已解码图片保持可见，加载提示缩为角落徽标，缩放值保持；浏览器延迟读取期间仍显示旧图，提示面积约为图像面积的 1%–2% |
| 关闭弹窗时先移除视频/原图，淡出动画中出现空白 | 视频先暂停并保留最后画面，媒体宿主移除后才收回；图片在原图宿主仍存在时保留呈现尺寸和内联静态占位，动画完成后归还原图 |
| 刷新状态的出现会再次清空并绘制未改变的视频缩略图 | 分开监听缩略图与弹窗画布；回归断言旧封面的绘制次数在新内容解码前保持 1 |
| 连续切换后，已离开任务的未发出请求仍占用队列 | 跳过无显示者的普通排队预览，保留已发出读取与显式刷新；新增断言修复前读取 5 次，修复后仅已发出的第一次和最终任务两次 |
| 替换/清理缓存只匹配 contextId 和 artifactId，可能让其他会话或轮次相互失效 | 改为完整身份匹配及元组键；同名、局部 ID 相同的任务各自保留资源，清理其中一个不会影响其他任务 |
| 快速出入场时，旧工具栏或测量回调可能继续响应 | 出场中的窗口不接受新的刷新/视频保存；图片观察者只接受当前窗口代次的回调 |

## 浏览器实际媒体验证

使用 `tests/visual/chat-artifact-videos/`，复用真实组件和主题。六个独立任务使用相同文件名，
分别对应红、蓝、绿的普通合成 H.264/PNG；客户端只模拟原生返回地址和普通延迟，不连接生成服务。
观察器读取真实 HTMLVideoElement 的 paused、currentTime 和连接状态，显示在验收页中。

- 六任务首次读取后连续切换 18 次，六项读取计数均保持 1；图片 URL 与所选任务匹配，视频封面始终就绪。
- 同一视频快速开关四次，源地址及读取计数保持不变。每次关闭均 paused=true；最后一次停止在 0.27 秒，后续检查时间仍为 0.27 秒。
- 图片刷新暂停返回结果时仍显示旧图；快速关闭重开保留原图，读取计数维持 2（首次＋本次刷新），完成后仅替换为第二个地址。
- 视频刷新开始后活动播放器数立即为 0；刷新等待中关闭重开不增加读取，完成后由当前窗口播放正确的视频，关闭后再次暂停。
- 按原 4 分钟复用期限发生的一次播放器续期单独计入，没有将必要续期冒充重复读取或承诺永久免读。
- 从空缓存快速经过多个尚未就绪任务后停在绿色视频：已经发出的蓝色视频、红色图片读取正常完成，
  未发送的蓝色图片读取被跳过；最终绿色视频正确就绪，无跨任务内容混用。
- 在 1180×760 下检查亮/暗主题、100%/200% 缩放和窄列。200% 弹窗为 1116×696，四边保留 32 物理像素；
  刷新徽标只占角落，旧图与缩放提示保留。关闭动画开始后原图和内联占位均仍存在。
