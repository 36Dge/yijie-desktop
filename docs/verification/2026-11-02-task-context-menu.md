# 任务右键菜单与标题选择修复

`contract-impact = none`：仅调整Desktop内部事件处理、弹层与操作目标。重命名/置顶复用既有Native命令及参数；永久删除沿用确认和清理流程。Native/API/Agent Host wire、权限、持久化格式、已查看记录及模型请求均不变。此前未提交的对话样式与交互修改保留。

## 原因与修复

1. 原 `hasMenu` 同时要求任务为当前路由，且 `preventDefault` 位于此判断之后。右击未打开的任务会提前返回，WebView因而显示系统文字菜单。现在任意有权限的任务都可打开易界菜单；任务整行统一阻止原生contextmenu，即使无操作权限或正在操作也不回落到系统菜单。
2. 任务标题没有禁用文字选择。现在仅在任务行设置标准及WebKit `user-select: none` 并阻止 `selectstart`，清除该标题范围内的旧选区；正文和重命名输入框的选择/编辑不受影响。Control-click作为菜单手势处理，不导航也不确认查看。
3. 解除“仅当前任务”限制后，原先依赖当前会话的重命名/置顶可能作用于错误任务。新增进程内显式sessionId操作入口，使用既有Native命令，继续检查权限、已授权列表/当前目标及清理状态。重命名、置顶不改变当前正文；永久删除确认后先导航并核对目标，取消导航或目标变化时不调用删除。
4. 同一时间只保留一个任务/项目菜单；保留Shift+F10、菜单键、Escape、Tab及取消弹窗后的焦点恢复。
5. 120%实测发现原任务菜单直接挂body，使指针坐标再被缩放一次，菜单底部达到769px，超出760px视口。改为与项目菜单共用现有反向缩放浮层，菜单内容独立按UI比例缩放。修复后同场景菜单范围为x142–352、y523–666，完整位于视口内。
