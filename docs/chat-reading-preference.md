# 对话完成提示的本地已查看记录

`contract-impact = additive`。用户要求点击左侧任务后移除完成提示并定位最新一轮。本次新增 Desktop 普通 UI 偏好，不修改 Native/API/Agent Host wire、权限、模型输入输出、会话数据库或重放事件。Owner / producer / consumer 均为 Desktop。公共 Contracts pin 为 N/A；权威源是 `src/domain/chat-reading-preference.ts` 的 schemaVersion 1。

## 格式与兼容

- Web Storage key：`yijie.desktop.ui.chat-reading.v1`，独立于侧栏折叠和目录偏好。
- 值：`{ "schemaVersion": 1, "entries": [{ "sessionId": "UUID", "activityAt": 100, "turnId": "UUID或null" }] }`。
- 只存本机已查看会话的随机标识、轮次标识和原生最近活动时间，不存正文、标题、路径、账号、租户标识、凭据或授权信息。只有当前 Native scope 已授权返回的会话会参与呈现，记录不授予任何读取权限。
- 点击后先按当前列表快照清除圆点；对应历史完成渲染后补齐最新轮次标识。查看记录不发给模型、Host 或其它服务。
- 新版本从缺失 key 开始，不迁移既有会话；旧版本忽略该 key。回滚只会失去已查看提示效果，业务数据和状态不变。重新升级可继续读取同版本偏好。
- 未知 schema/不可读值保留原值，不覆盖未来格式；存储不可用时保留当前进程内的已查看效果，不能保证跨重开恢复，不阻塞任务导航。

## 状态与定位

圆点要求最新状态严格为 `completed`，并且没有匹配的查看记录。读取持久记录后，列表活动时间用于识别后续变化；已加载会话用轮次标识区分新旧完成。Native 读取同一已完成轮次可能更新活动时间，确认轮次相同后更新查看快照，避免把同步误当成新完成。显式新一轮排队/运行会清除旧查看记录，即使两轮的秒级时间相同也重新提示。失败、中断和未知状态不显示完成圆点。

每次成功点击侧栏任务都创建一次内存中的定位意图；重复点击当前路由同样生效。导航取消不确认查看。新点击取代旧意图，跨授权上下文变化取消未完成意图。

页面等待路由、已选会话、历史与实际渲染的轮次一致后定位到最新一轮；使用真实滚动容器的原生锚点定位，兼容缩放及右侧分栏。定位取消待执行的自动跟随帧；长回答停在该轮起点，不自动跳至回答末尾。已有精确轮次深链继续按原规则处理，侧栏点击清除深链参数后回到最新一轮。

原生状态源沿用现有 `ChatSession.latestTurnStatus`、`lastActivityAt` 和已加载时间线的 `turnId`，未增加 Native command、DB schema、后台轮询、依赖或网络目标。离线期间只有列表元数据且活动时间未变时无法识别未观察到的同秒新轮次；加载该会话后以真实轮次标识校正，不通过猜测或额外模型请求生成状态。
