# 任务目录侧栏菜单审计与修复

日期：2026-10-03。范围：Desktop 侧栏项目树，不改变定时任务执行、授权或文件管理。

## 审计结论

缺少菜单是旧实现有意限制后留下的功能缺口，不是权限读取失败。

1. `src-tauri/src/chat/schedules/workspace.rs` 将用户项目和 `managed_schedule`
   托管目录分开。普通项目列表的 `user_filter` 不返回托管目录，`require_user` 拒绝其
   置顶、移除及书签操作，避免把运行时工作目录当作用户授权的目录管理。
2. `src/domain/chat-sidebar-history.ts` 从会话的 `projectId` 补出不在普通项目列表里的
   可用目录，标注 `project: null`，统一显示“任务目录”。
3. `ChatSidebarTree.vue` 旧菜单条件要求 `group.project` 非空，故该分组没有操作入口。
   旧组件测试明确要求该入口不存在；原生 preparation 测试也要求普通置顶/移除拒绝托管目录。
4. 普通移除会设置 `chat_projects.removed_at`，而定时执行的工作目录解析、目标绑定校验
   都要求该字段为空。直接放开原生移除限制会使已关联的计划无法继续使用工作目录。
5. 普通项目原先实际绑定的是“…”点击菜单；本次也补齐项目行右键和 Shift+F10/菜单键触发，
   让两类目录都能按用户期望操作。

## 实现语义

- 用户选择的项目仍调用原有原生接口。
- 托管任务目录复用侧栏 UI 偏好存储，只保存目录的显示置顶/移除状态。
- “置顶项目/取消置顶”与普通项目按置顶时间共同排序，显示同样的置顶图标。
- “移除”保留确认弹窗；只移除侧栏分组，该目录的全部会话按原会话顺序平铺到所有目录之后。
  分页或新会话刷新后仍应用此规则；不会改变会话的 `projectAvailable`、项目关联或运行状态。
- 文件、工作目录、定时任务、会话内容、运行授权、书签和原生数据库均不修改。
- 沿用 `pin_project` / `remove_project` 权限门控；权限或绑定上下文变化时关闭菜单/确认。
  偏好保存失败时不提交内存状态，并显示错误，避免显示成已保存。
- 偏好只对当前原生会话列表中、未列入用户项目选择器的目录生效。
  其他目录 ID 不生成新行，也不为用户项目覆盖原生状态。

## 契约与兼容

`contract-impact = additive`：新增应用本地 UI 偏好格式，没有公共 wire/native IPC 变更。
Owner/producer/consumer：Desktop `sidebar.store` / `ChatSidebarTree`；所有变更位于本仓。
公共 contracts PR/tag/pin：N/A，未改变 API、Agent Host、Runtime 或原生 command。

唯一权威源：`src/domain/task-directory-preference.ts`，版本 1；已有侧栏折叠状态键保持不变。

存储键 `yijie.desktop.ui.task-directories.v1` 的格式为：

```json
{
  "schemaVersion": 1,
  "entries": [
    {
      "projectId": "019c1a00-0000-7000-8000-000000000001",
      "pinnedAt": 1791000000,
      "removed": false
    }
  ]
}
```

`projectId` 为原生不透明 UUID；`pinnedAt` 为非负整数秒或 null；`removed` 为布尔值。
移除时清除置顶时间，取消置顶且未移除时删除默认条目。没有标题、路径、正文或身份凭据。
该偏好不是授权依据，必须与当前已授权的原生列表相交后才影响展示。

缺失键无需迁移，沿用旧布局。未知版本、无效格式或读取失败时显示默认布局，并禁止覆盖
该存储值；正常重启可恢复已保存状态。旧构建忽略独立的新键，回滚只恢复旧侧栏展示，不影响
原生数据和定时执行；重新升级后仍可读取原偏好。无数据库升级/降级或跨仓激活顺序要求。
